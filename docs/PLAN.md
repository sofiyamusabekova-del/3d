# План реализации — планировщик квартиры

Основание: [PRD](PRD-interior-planner.md), [SPEC](SPEC.md), [Tasks](Tasks.md). Этот файл не заменяет Tasks.md (там чекбоксы и журнал), а группирует 25 этапов в вехи и показывает, что можно сделать раньше.

Состояние: папка проекта `D:\proweb\3d` была пустой, кода нет. Node 24.21, npm есть.

## Стек (SPEC §4)

React + TypeScript + Vite · Three.js + React Three Fiber (+ Drei) · SVG для 2D · Zustand · Vitest (геометрия) · Playwright (e2e, Chrome и Edge) · three-gpu-pathtracer для «Качественного снимка». Версии фиксируются lock-файлом на этапе 2.

## Структура репозитория

```
docs/            PRD, SPEC, Tasks, PLAN, ASSETS.md (реестр лицензий)
src/domain/      модель квартиры, команды, история, валидаторы (без React/Three)
src/geometry/    чистые функции: контуры, пересечения, коллайдеры, допуски
src/plan2d/      SVG-план
src/scene3d/     R3F-сцена, камера, прогулка, небо, свет
src/ui/          мастер, панели, каталог, тёмная тема
src/catalog/     метаданные и GLB (public/models)
tests/           модульные и e2e
```

Главное правило: 2D и 3D читают одно состояние; геометрия не знает про React.

## Предлагаемые изменения порядка (нужно ваше согласие)

Tasks.md ставит этапы 20–25 после приёмки. Три из них дешевле сделать раньше, иначе придётся переделывать готовое:

1. **D-15 (схемы ×1,1)** — внести сразу в этап 7.2, когда создаются схемы. Этап 22 тогда сводится к проверке и обновлению таблицы §3.1.
2. **D-16 (покрытие пола)** — поле в модели и шаг истории заложить в этапе 3, UI оставить на этап 23. Иначе меняем схему данных после приёмки.
3. **D-13 (тёмная тема)** — переменные оформления завести на этапе 2–3 (токены цвета, типографика), а не красить всё в конце. Этап 25 остаётся полировкой и проверкой контраста.

Если порядок остаётся как в Tasks.md, ничего не меняется, но стоимость переделок выше.

## Что делать первым (ближайшие шаги)

1. Этап 1: подтвердить решения. По SPEC D-01–D-17 уже решены, поэтому достаточно записи «подтверждено» и ответов на вопросы ниже.
2. Этап 2: `npm create vite` (React + TS), зависимости, Vitest, Playwright, README с командами, `proweb-skills` по PRD §14.
3. Этап 3: модель квартиры и единицы (3.1–3.6), сразу с тестами.
4. Этап 4: прототип одной комнаты. Это точка принятия решения о продолжении.

## Правила работы (из Tasks.md)

- Один этап за раз; следующий начинается после вашего подтверждения.
- Чекбокс ставится только после проверки; запись в журнал обязательна.
- Новые решения идут в SPEC §3, изменения объёма в PRD.
